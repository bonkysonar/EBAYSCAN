# Seller Hub research recovery

Browser tabs and numeric browser handles are temporary. The durable identity is the previously authorized extension-instance metadata, followed by the visibly verified seller handle. A reported profile name must match the authorized profile; an omitted optional profile label does not discard an otherwise unique exact extension match. It permits selecting a task-owned tab for seller verification, never skipping the visible seller check. A missing or different extension, conflicting profile name, or duplicate extension match still blocks. The operational manifest is `exports/arbitrage-finds/research-session.json`, outside every learning store. It contains no passwords, cookies, account pages, listing evidence or buyer data.

## One attempt

1. Read `RETAIL_ARBITRAGE.md`, `SOLD_HISTORY.md`, the saved context and current automation instructions. For an authorized publication run, run `node scripts/runRetailWorkflow.mjs --preflight` once. For local validation use `--localOnly` on startup and finish, and omit preflight; this suppresses operational POSTs and publication while retaining final artifact validation. A successful CLI startup is preparation, not completed browser research.
2. Inspect `node scripts/manageRetailResearchSession.mjs status`. Acquire ownership before changing files. On the first acquisition supply the authorized profile binding; later acquisitions retain it:

   ```powershell
   $researchLease = node scripts/manageRetailResearchSession.mjs acquire --ownerThread=<current-chat-id> --profile=<authorized-profile-name> --extension=<observed-extension-instance> --seller=<expected-seller-handle> | ConvertFrom-Json
   $env:RETAIL_RESEARCH_OWNER = $researchLease.ownerToken
   ```

   This nonce is local coordination data, not an eBay credential. Each shell invocation and the inbox process must receive it. Do not share an owner nonce with another chat. A live lease rejects acquisition. For an expired lease, use the chat status tool to verify the exact previous owner is inactive, then supply a local `--previousOwner=<json>` containing `ownerThreadId`, `ownerAttemptId`, `status` (`idle`, `completed`, or `interrupted`), and the actual `verifiedAt` within the last minute. Missing, unknown or active status cannot reclaim a lease. Expiration alone is insufficient.
3. Run exactly one startup command: `node scripts/runRetailWorkflow.mjs --full` for fresh discovery, or `--resume=<exact-saved-context>` for a draft no older than 24 hours. Add the normal browser observation path if available. `--full` always starts a new scan; it cannot silently resume the old backlog. The default sale-radar cohort selects up to 12 distinct album queries, reserving one third of capacity for fresh deal-feed events when available. The full discovery pool remains in the private draft, with deferred counts. Old offers are not carried into today's required cohort; their original drafts and checkpoints remain intact, and fresh matching captures can be reused without changing timestamps. The runner binds the new run/context/checkpoint only after its durable supersession links identify the exact previous run. An arbitrary switch still fails. Original data observation times remain separate from this attempt's start.
4. Refresh browser inventory. Select exactly one matching profile/extension. Do not select by numeric handle or use another profile. Save a sanitized observation JSON with the actual `observedAt` (within the last minute) and only `browsers:[{id,profileName,metadata:{extensionInstanceId},tabs:[{id}]}]`, then call `node scripts/manageRetailResearchSession.mjs observe --observation=<json>`. Avoid storing unrelated tab titles, URLs or account pages.
5. Follow the returned decision. `create_tab` means create a new task-owned tab in that same browser at the next generated query/window URL. `verify_tab` means inspect the saved workflow tab. A hint from an older completed run is never reused as a requirement. Do not commandeer an active chat's tab.
6. Inspect the seller identity visibly. Add the observed `browserId`, `tabId`, `taskOwned:true`, `sellerHandle` and `nextTaskId` to the observation, and run `observe` again. Set `authenticationRequired`, `challenge`, `disconnected`, or `captureRepair` only for an actually observed condition. Missing/ambiguous profiles, wrong seller, real login, challenges, disconnection and capture defects remain distinct blockers. `tab_missing_recoverable` is not a failure. Both manifest and saved context retain the actual blocker and retry time. Never bypass challenges or rotate credentials as tab recovery.
7. Start the local observation inbox with the owner nonce in its environment. A prior inbox must be confirmed idle and restarted with the new owner's nonce; never use an old unguarded server. Every POST and importer/planner/curator command shares a process mutex. A busy writer is retriable, not an empty result. The mutex is inherited only by synchronous workflow child commands and released on exit. Dead-process locks can be reclaimed after checking their PID; malformed locks fail closed.
8. Work the newly generated interleaved order. Save cumulative observed rows after each pagination page with `complete:false` until every page and control is verified. Retain original observation times. Duplicate rows, missing links, unknown windows and missing controls still fail existing validation. Explicit empty Sold results are completed collection only after observing Sold/New/Vinyl and the actual dates, never positive sales evidence.
9. Renew with `node scripts/manageRetailResearchSession.mjs renew` at least every ten minutes during browser collection. Rebuild the exact plan after small batches. Continue the exact fresh cohort within the attempt. Inspect `plan.metrics`: wall-clock interval collection rate, freshness losses, remaining-time estimate and oldest pending date. An estimate is null without measured positive throughput. This includes downtime and is not an active-browser benchmark. Historical collection stays separate from fresh evidence. Evidence freshness limits remain unchanged; an expired acquisition draft needs a new scan rather than repeated research against its old prices.
10. Inspect every `editionReviews` entry. For actually reviewed incompatible or still-unconfirmed editions use `node scripts/recordRetailEditionReview.mjs <exact-plan> <review-id> incompatible_unpriced` or `unconfirmed_unpriced`, then rebuild. These outcomes never create prices or alter matching. The opaque review identity binds the offer and captured evidence; changed evidence reopens review. A supported match must come through ordinary captured evidence and the matcher. No bulk auto-resolution.
11. Only when all tasks and edition reviews for the selected current cohort have outcomes, finish the exact context through the existing active-market, retailer, curation and final validation steps. Authorized publication then uploads and verifies the run ID/hash; `--localOnly` stops at validated local output. External blockers do not exempt the completion or purchase-evidence gates. The runner refuses an expired draft before finish. Preserve the sanitized `failure.code`, `failure.stage` and timestamp if a step fails; do not replace them with a generic successful invocation report. Release ownership with `node scripts/manageRetailResearchSession.mjs release` on completion or a documented interruption/blocker, leaving the checkpoint intact. Stop the task's inbox before releasing. Separate invocation, collection, publication and verified readback outcomes in the receipt.

The 240-task planner setting remains a maximum batch size; it does not enlarge the default 12-album acquisition cohort. An album may require an additional A-side query or a justified annual follow-up. All tasks for selected offers must finish; unselected discoveries and historical offers are explicitly deferred, never called completed research. A deliberate `--mode=comprehensive` scanner run is a broader diagnostic scope, not the daily default. Browser retailer repairs may need fresh recapture; their six-hour window is unchanged.

## Reliability proof

Unit tests are not overnight evidence. On each of the next two scheduled wakeups, record the attempt/thread ID, selected current run and its age, fresh profile binding, before/after queue counts, accepted captures, browser recovery decision and publication result. Confirm a draft older than 24 hours is replaced with fresh discovery rather than resumed indefinitely. During one wakeup, after saving incomplete page state, deliberately close only that attempt's task-owned research tab. Refresh inventory, recreate it in the verified profile, restore the next saved task URL and verify seller/controls/dates before continuing. Record no raw account pages or credentials. Claim recurring recovery verified only after both scheduled attempts show useful progress without manual tab restoration. Report measured freshness-capacity shortfalls honestly.

Run `npm test` and `npm run build`. The session, workflow, persistent-queue and browser-capture suites exercise ownership races, expiry/reclaim, wrong-profile selection, retired-tab hints, wrong-run checkpoints, stale captures, non-positive empty results and unpriced edition outcomes.
